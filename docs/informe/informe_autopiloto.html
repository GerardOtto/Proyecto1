1. Resumen ejecutivo

Se construyó un autopiloto (npm run autopilot) encima del motor existente. Produce episodios con el mismo formato del demo: saludo "¡Papu papu!", rótulo con palabra clave, meme, explicación por turnos, remate y llamada a la acción. En cada episodio varía:

  • personajes y roles (presentador, contraparte y, a veces, invitado), sin repetir la misma pareja;
  • colores (cinco temas visuales con fondos animados y gráficos propios);
  • efectos de sonido, colocados según la reacción, la sección y el personaje;
  • tema: noticias de IA e informática o, si no hay, conceptos de Computer Science, IA, programación, polémicas e historia.

Qué se verificó en este entorno

  • Se planificaron y escribieron 3 episodios distintos (temas, parejas, paletas y formatos), todos válidos para el motor.
  • Un episodio (AlphaGo vs Lee Sedol) se produjo de punta a punta: voces de prueba (flite), reajuste a 67,6 s con el audio real, render en ~5 min y QA con todos los checks hard en PASS (licencias en aviso).
  • 190 tests en verde. Entre ellos, uno que genera y valida un guion para cada uno de los 29 temas del banco (duración de 62 a 115 s, rótulo que cabe, turnos correctos). Lint y typecheck limpios.

Lo que no se pudo probar aquí (sin red ni claves)

La lectura real de feeds de noticias, el escritor con Claude (sí se probó con un proveedor simulado), las voces de Fish Audio y el modelo de whisper.cpp. Todo está implementado, pero su primera corrida debe hacerse en tu máquina (sección 6).

2. Cómo funciona

1 · FuentesRSS/Atom de medios en español e inglés → puntuación por nicho y frescura → agrupado de la misma noticia en varias fuentes.
2 · Banco evergreenSi no hay noticias nuevas (o no hay escritor LLM): 29 temas con datos verificables y fuentes.
3 · PlanTema + formato + casting por roles + tema visual. Determinista: no repite tema, pareja ni paleta.
4 · GráficosTarjetas propias (cifra, ideas clave, código, comparación, titular) con la paleta del tema. Licencia propia.
5 · GuionEscritor de plantilla (gratis, sin conexión) o escritor LLM (noticias), en el formato del motor.
6 · SFXReglas por tags: shock → golpe dramático, risa → risa, idea → ding, firma de Teto, sin pasarse de 7.
7 · RevisiónLint editorial + validador del motor. El episodio queda en needs_review.
8 · Producción--produce: voces, transcripción, reajuste al audio, render y QA (pipeline existente).
9 · PublicaciónTextos para TikTok, Instagram y YouTube, hashtags, comentario fijado, horario (CDMX) y checklist.
npm run autopilot                                   # 1 episodio listo para revisar
npm run autopilot -- --batch 3                      # semana tipo (máx. 1 noticia)
npm run autopilot -- --episode <id> --produce       # producir tras revisar
npm run autopilot -- --check-feeds                  # probar las fuentes de noticias
npm run autopilot -- --make-backgrounds             # fondos de los temas visuales
npm run avatars:ingest -- --character rin --from <carpeta de renders>

Recomendado

  • Avatares de Rin y Len (y de nuevos personajes): renders con fondo claro uniforme, nombrados por reacción (neutral.png, feliz_2.png…), y luego npm run avatars:ingest.
  • Más SFX con tags (risa, idea, transición, error, éxito) de una biblioteca con licencia. El director los usará sin tocar código.
  • Ampliar el banco evergreen a 50–80 temas (≈ 4–6 meses a 3 videos por semana sin repetir). Los tests validan cada tema nuevo.
  • Plantillas de humor por personaje (frases de firma, malentendidos típicos) para reforzar las personalidades.

Bloqueante para monetizar: licencias

Hoy el reporte marca commercialUse: blocked. Los avatares (renders MMD), la mayoría de los SFX, los memes y los GIFs de gatos tienen licencia unknown. Las ilustraciones oficiales de Miku, Rin, Len y Luka usan CC BY-NC (no comercial), y Teto tiene guías propias. Antes de activar Creator Rewards o YouTube Partner: reemplaza los SFX y memes por material licenciado, documenta el origen de cada avatar y revisa las guías de Crypton y de Teto para la monetización.

6. Primera corrida en tu máquina (checklist)

  1. git pull y npm install. Python con Pillow, numpy y scipy si vas a ingerir avatares.
  2. npm run doctor y npm test (deben dar 190 en verde).
  3. npm run autopilot -- --check-feeds: corrige las fuentes que fallen.
  4. npm run autopilot -- --mode evergreen --tts files (o --tts fish): revisa projects/ep_…/script.md y autopilot.json (avisos, SFX elegidos, notas).
  5. Si el guion te convence: npm run autopilot -- --episode <id> --produce. Si no, edítalo a mano y produce.
  6. Con ANTHROPIC_API_KEY: npm run autopilot -- --mode news. Verifica cada línea de factClaims contra las fuentes.
  7. Publica con output/<id>/publish/ (textos, horario y checklist). Marca el episodio como publicado en el historial (por ahora a mano).

7. Consejos

Calidad y confianza

  • Nunca publiques sin revisar. En noticias, un error factual cuesta más que un video menos. El escritor LLM solo puede usar los hechos del brief, pero aun así puede equivocarse.
  • Etiqueta siempre el contenido de IA en las tres plataformas (las voces imitan a personajes con voces humanas detrás). Es barato y la comunidad Vocaloid lo valora.
  • Varía de verdad. YouTube penaliza el contenido masivo y con plantilla ("contenido no auténtico"). Alterna formatos, edita remates a mano y añade de vez en cuando episodios especiales hechos a mano.
  • Evita chistes sobre nacionalidades y política. El prompt del guionista lo prohíbe y la regla de SFX para confusión excluye los memes con tag "china". Revisa también los SFX marcados a mano.

Producción

  • Lotes semanales: un día, --batch 3 + revisión (≈ 45 min); otro día, producción. Las noticias "calientes" van aparte y se publican de inmediato.
  • Haz crecer el banco evergreen con temas que pida tu audiencia en los comentarios: es contenido gratuito, determinista y siempre disponible.
  • Cuida el historial (history.json) en git: es lo que evita repetir temas y parejas.
  • Mide y ajusta: retención, envíos por alcance y "visto frente a deslizado" (docs/10). Cambia una sola variable a la vez (formato, pareja, horario).

Técnicos

  • No automatices capturas de artículos: riesgo de copyright, muros de pago y banners. Las tarjetas de titular propias son seguras.
  • Remotion está fijado en 4.0.530 a propósito (4.0.531 rompe Studio). Comprueba Studio antes de actualizar.
  • Si ejecutas como root (Docker/CI), Chrome necesita --no-sandbox; ya se aplica automáticamente en la generación de gráficos.
