# 08 — QA y criterios de aceptacion

La tabla se calcula en `src/pipeline/report.ts` y se guarda en `report.json > qa`.

| Check | Condicion | Tipo | Donde se verifica |
|---|---|---|---|
| Duracion | 60.0 <= duracion <= 120.0 s | Hard | timeline final + MP4 (ffprobe) |
| Formato | 1080x1920, 9:16, H.264/AAC, 30 fps | Hard | MP4 (ffprobe) |
| Audio | sin clipping (pico < 0 dBFS), A/V sincronizados (< 250 ms), no mudo | Hard | MP4 (volumedetect) |
| Subtitulos | sin texto fuera de safe area; color correcto por personaje | Hard | layout estimado + plan |
| Avatar | cada personaje usa una reaccion valida del catalogo | Hard | timeline + catalogo |
| Assets | sin paths rotos ni imagenes vacias | Hard | catalogo + plan |
| Contrato | timeline valido contra schema, sin solapes ni eventos invalidos | Hard | ajv + semantica |
| Narrativa | existe hook + desarrollo + cierre | Hard | secciones |
| Humor | al menos una interaccion/reaccion/punchline intencional | Soft | eventos/secciones |
| Performance | el render termina sin errores y el MP4 decodifica entero | Hard | `ffmpeg -f null` |
| Reproducibilidad | mismo timeline + assets => mismos fotogramas | Hard | `render --repro` |
| Licencias | assets/voces con licencia documentada | Soft | catalogo |

Comandos: `npm run validate -- --project P` (sin render), `npm run validate -- --project P --output`
(MP4 existente), `npm run render -- --project P --repro`.

## Tests automaticos (`npm test`)
| Archivo | Cubre |
|---|---|
| tests/schemas.test.ts | Schemas de timeline, characters, assets, reactions, render; ejemplo del plan |
| tests/frames.test.ts | Conversion de timestamps a frames, contiguidad |
| tests/duration.test.ts | Duracion minima/maxima, ajuste de silencios, acciones extend/compress |
| tests/catalog.test.ts | Resolver asset/personaje/reaccion por ID, alias, paths rotos, imagenes vacias, assets de proyecto |
| tests/captions.test.ts | Color de subtitulo por personaje, paginado, safe area, enfasis |
| tests/script-parser.test.ts | Guion de referencia del plan, directivas, errores con linea |
| tests/align.test.ts | Alineado guion <-> whisper, interpolacion |
| tests/plan.test.ts | Determinismo del plan (hash), roles/lados, reacciones, memes, visuales |
| tests/validation.test.ts | Narrativa, avatares, assets, personajes en pantalla, eventos, audio |
| tests/llm-director.test.ts | Director LLM con proveedor simulado: schema, conversion, reintentos |
| tests/build-timeline.test.ts | Reajuste con audio: contiguidad, captions absolutos, pausas, DurationError |
| tests/render.smoke.test.ts | Render real de 8 s (solo `npm run test:render`) |

Fixtures: `tests/fixtures/smoke.timeline.json` (8 s, render de humo),
`tests/fixtures/pdf-example.timeline.json` (ejemplo de la seccion 6).

## Validacion visual manual del MVP
- Abrir el render completo y revisar hook, transiciones, meme y cierre.
- Revisar subtitulos en pantalla de telefono o preview equivalente (`npm run render -- --safe-area`
  dibuja la safe area).
- Comprobar que los cambios de avatar tienen intencion narrativa y no parecen aleatorios.
- Criterio de calidad del piloto: se entiende el concepto sin leer el guion, se reconoce quien habla
  por color/subtitulo y reaccion visual, y la secuencia narrativa se percibe intencional.
